# Chainslake Warehouse — Docker Installation Guide

This document provides step-by-step instructions for installing **Chainslake Data Warehouse** on a local machine using Docker Compose.

---

## System Requirements

- **Docker** >= 20.10
- **Docker Compose** >= 2.0
- Minimum RAM: 8 GB (16 GB recommended)
- Free disk space: minimum 20 GB

---

## System Architecture

The system consists of 4 main Docker services:

| Service | Description | Port |
|---|---|---|
| `postgres` | PostgreSQL database — stores metadata for Airflow, Hive Metastore and Metabase | 5432 (internal) |
| `node01` | Primary Hadoop node: runs HDFS NameNode + DataNode, Airflow, Trino, Hive, Spark | 58080, 59870, 59001 |
| `node02` | Secondary Hadoop node: runs HDFS DataNode | — |
| `metabase` | Metabase application for querying data and creating visualizations | 53000 |

---

## Step 1: Prepare Environment Configuration

### 1.1. Create `.env` File

Copy the example file and edit for your environment:

```bash
cp env_example .env
```

`.env` file contents:

```env
# PostgreSQL password (use a stronger password in production)
POSTGRES_PASSWORD=postgresexamplepassword

# PostgreSQL data directory
POSTGRES_DATA_DIR=./postgres_data

# HDFS data directories for each node
NODE01_DATA_DIR=./hadoop_data_node01
NODE02_DATA_DIR=./hadoop_data_node02

# Container paths
CHAINSLAKE_HOME_DIR=/home/hadoop/projects/chainslake
CHAINSLAKE_RUN_DIR=/home/hadoop/projects/chainslake-run
```

---

## Step 2: Prepare Metabase Driver

Run `download_lib.sh` to download the Metabase JDBC driver:

```bash
bash download_lib.sh
```

This script:

1. Creates `libs/`.
2. Downloads the Starburst Metabase driver JAR from GitHub — required for Metabase to connect to Trino.

The data directories `hadoop_data_node01/`, `hadoop_data_node02/` and `postgres_data/` are auto-created by Docker Compose on first start.

After running, the directory structure will be:

```
docker/
├── hadoop_data_node01/      # HDFS data for node01 (auto-created by Docker)
├── hadoop_data_node02/      # HDFS data for node02 (auto-created by Docker)
├── libs/                    # Metabase JDBC driver (created by download_lib.sh)
├── postgres_data/           # PostgreSQL data (auto-created if not present)
├── etc/                     # Service configuration files
├── docker-compose.yml
├── .env
└── download_lib.sh
```

---

## Step 3: Start Services

```bash
docker compose up -d
```

Docker Compose will create and start all services. Expected result:

```
✔ Network chainslake-onprem-network  Created
✔ Container chainslake-onprem-postgres-1  Started
✔ Container chainslake-onprem-node02-1    Started
✔ Container chainslake-onprem-node01-1    Started
✔ Container chainslake-onprem-metabase-1  Started
```

Check container status:

```bash
docker compose ps
```

All containers should be `Up`:

```
NAME                           SERVICE    STATUS    PORTS
chainslake-onprem-postgres-1   postgres   Up        5432/tcp
chainslake-onprem-node02-1     node02     Up
chainslake-onprem-node01-1     node01     Up        0.0.0.0:58080->8080/tcp, 0.0.0.0:59001->9001/tcp, 0.0.0.0:59870->9870/tcp
chainslake-onprem-metabase-1   metabase   Up        0.0.0.0:53000->3000/tcp
```

## Step 4: Verify Supervisord (localhost:59001)

**Supervisord** is the process manager for services running inside `node01`. After starting, access:

```
http://localhost:59001
```

### Login Credentials

Get username and password from `etc/supervisord_node01.conf`:

```ini
[inet_http_server]
port=0.0.0.0:9001
username=supervisord
password=supervisord@password
```

| Field | Value |
|---|---|
| Username | `supervisord` |
| Password | `supervisord@password` |

### Managed Services

After logging in, you'll see the list of services and their status. All must be **RUNNING**:

| Service | Description |
|---|---|
| `airflow` | Airflow scheduler & web server |
| `hdfs-namenode` | HDFS NameNode |
| `hdfs-secondarynamenode` | HDFS Secondary NameNode |
| `hdfs-datanode` | HDFS DataNode on node01 |
| `hive-metastore` | Hive Metastore service |
| `spark-thriftserver` | Spark Thrift Server (JDBC/ODBC) |
| `trino` | Trino query engine |

> **Note:** Services may take 1–2 minutes to fully start after container launch. If some services show `STARTING`, wait and refresh the page.

## Step 5: Verify Airflow (localhost:58080)

**Apache Airflow** is used for scheduling and managing data pipelines. Access:

```
http://localhost:58080
```

### Login Credentials

| Field | Value |
|---|---|
| Username | `admin` |
| Password | See description below |

The password is auto-generated by Airflow on first run. Read it with:

```bash
cat ../chainslake/airflow/standalone_admin_password.txt
```

Or from inside the container:

```bash
docker exec chainslake-onprem-node01-1 cat /home/hadoop/projects/chainslake/airflow/standalone_admin_password.txt
```

> **Note:** The `standalone_admin_password.txt` file only appears after Airflow has successfully started for the first time. If the file doesn't exist yet, wait 1–2 minutes and check the `airflow` service status on Supervisord.

## Step 6: Set Up Metabase (localhost:53000)

**Metabase** is a BI tool for querying data and creating visualizations. After all containers have started, run the setup script from the project root directory:

### 6.1. Prepare Credentials

```bash
cp script/env_example script/.env
```

Edit `script/.env` with actual values:

```env
METABASE_URL=http://localhost:53000
METABASE_EMAIL=admin@chainslake.com
METABASE_PASSWORD=<your_password_here>
METABASE_SITE_NAME=Chainslake Warehouse
```

### 6.2. Run Setup Script

```bash
python script/setup_metabase.py
```

The script automatically:
1. Waits for Metabase to be ready
2. Creates admin account
3. Creates API key and writes to `query/.env`
4. Adds SparkSQL and Trino connections
5. Authenticates Metabase CLI (`mb`)

**Optional parameters:**

```bash
python script/setup_metabase.py --skip-databases    # Skip adding databases
python script/setup_metabase.py --skip-cli          # Bypass CLI auth
```

### 6.3. Verify Results

- Access `http://localhost:53000` — login with admin credentials
- Go to **Settings** → **Admin** → **Databases** — verify Spark and Trino have been added
- File `query/.env` has `METABASE_API_KEY=...`

> **Note:** For step-by-step details and common errors, see `skill/setup-metabase.md`.

## Stop and Restart System

Stop all services:

```bash
docker compose down
```

Restart:

```bash
docker compose up -d
```

View logs for a service:

```bash
docker compose logs -f node01
docker compose logs -f metabase
```

## Common Troubleshooting

**Supervisord not showing all 7 services as RUNNING**

Services in node01 need time to start in sequence. Wait 2–3 minutes after `docker compose up -d`, then refresh the Supervisord page.

---

**Airflow `standalone_admin_password.txt` file not found**

This file is only created after Airflow starts successfully for the first time. Check Airflow logs:

```bash
docker exec chainslake-onprem-node01-1 tail -50 /tmp/airflow.log
```

---

**Metabase can't connect to SparkSQL**

Check Spark Thrift Server on Supervisord. If the service is not yet `RUNNING`, wait longer. You can try restarting the service from the Supervisord interface.
